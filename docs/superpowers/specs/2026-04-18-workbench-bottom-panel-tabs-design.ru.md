# Дизайн вкладок нижней панели верстака

## Цель

Заменить текущее поведение нижнего dock в полноэкранной IDE верстака на единую нижнюю панель с вкладками `Terminal` и `Inventory`, возможностью полностью скрывать панель и отдельными свойствами размера для каждой вкладки.

## Область изменений

Этот редизайн касается только IDE-экрана верстака.

Входит в задачу:

- единая нижняя панель внутри полноэкранной IDE верстака
- вкладки `Terminal` и `Inventory` внутри этой панели
- скрытое состояние панели, когда не показано содержимое ни одной вкладки
- отдельные свойства размера панели для вкладки terminal и вкладки inventory
- вычисление terminal viewport из bounds вкладки terminal, а не из старого dock bounds
- обновление фокуса и hitbox так, чтобы взаимодействие принимала только активная нижняя поверхность

Не входит в задачу:

- изменения обычного экрана компьютера
- произвольное drag-resize игроком в этой итерации
- дополнительные вкладки помимо `Terminal` и `Inventory`

## Текущая проблема

Текущая полноэкранная IDE верстака одновременно держит две разные нижние сущности:

- `inventoryBounds` для поверхности inventory
- `terminalDockBounds` для отдельного terminal dock над ней

Эта модель привела к UX-регрессии относительно ожидаемого поведения верстака:

- terminal уехал вверх в отдельную dock-зону
- нижняя область перестала вести себя как прежняя terminal-зона
- высота editor уменьшается terminal-dock'ом, а не одной общей нижней поверхностью
- размер terminal всё ещё зависит от исторической dock-модели, а не от видимой области вкладки

## Целевой UX

### Модель нижней панели

IDE верстака сохраняет недавно введённую полноэкранную editor-first оболочку, но нижняя часть становится одной общей панелью.

У нижней панели есть три состояния:

- `HIDDEN`
- `INVENTORY`
- `TERMINAL`

Активным может быть только одно состояние за раз.

Когда панель скрыта, editor расширяется вниз и занимает освободившееся место.

Когда панель видима, рендерится только содержимое активной вкладки.

### Поведение по умолчанию

Вкладка по умолчанию при открытии IDE верстака — `Terminal`.

Если панель была скрыта и пользователь нажимает кнопку вкладки, панель сразу открывается в выбранной вкладке.

Скрытие панели не должно сбрасывать:

- последнюю активную вкладку
- настроенную высоту панели для каждой вкладки

### Размеры по вкладкам

Высота нижней панели больше не является одной общей константой.

Вместо этого состояние верстака хранит два независимых свойства:

- `inventoryPanelHeight`
- `terminalPanelHeight`

Активная вкладка определяет, какая высота используется для `bottomPanelBounds`.

Это сохраняет единый визуальный регион панели для inventory и terminal, но позволяет вкладке terminal иметь другую высоту, чем вкладка inventory.

### Поведение terminal

Terminal больше не рендерится из отдельного dock над inventory.

Вместо этого:

- terminal-вкладка получает общие `bottomPanelBounds`
- content area terminal вычисляется из bounds контента terminal-вкладки
- terminal grid подгоняется под эту видимую content area

Terminal может принимать ввод только когда:

- нижняя панель видима
- активна вкладка `TERMINAL`
- текущая terminal interaction policy разрешает ввод

Переход с terminal-вкладки на другую вкладку или скрытие панели должны немедленно снимать terminal focus.

### Поведение inventory

Инвентарь игрока остаётся в нижней панели, но становится tab content вместо постоянно присутствующей зоны.

Только вкладка inventory открывает взаимодействие со слотами инвентаря.

Когда активно состояние `TERMINAL` или `HIDDEN`, слоты inventory не должны оставаться интерактивными в той же области экрана.

## Архитектура

### Изменения состояния

`WorkbenchState` должен заменить текущий terminal-only флаг видимости на состояние нижней панели, которое может выразить все три UX-состояния.

Рекомендуемая модель:

- `bottomPanel: WorkbenchBottomPanel`
- `inventoryPanelHeight: Int`
- `terminalPanelHeight: Int`

Где `WorkbenchBottomPanel` — enum со значениями:

- `HIDDEN`
- `INVENTORY`
- `TERMINAL`

`terminalVisible` после миграции становится лишним и должен быть удалён.

### Ответственность store

`WorkbenchStore` начинает отвечать за:

- переключение активных нижних вкладок
- скрытие и показ панели
- сохранение высоты для каждой вкладки
- косвенный сброс terminal focus через screen flow, когда terminal-вкладка перестаёт быть активной

Store должен отдавать явные действия, а не переиспользовать старую бинарную семантику переключателя terminal.

Ожидаемая поверхность действий:

- показать вкладку inventory
- показать вкладку terminal
- скрыть нижнюю панель

Предыдущий API `toggleTerminalVisibility()` должен быть заменён или временно сведён к тонкой совместимости на время миграции.

### Ответственность layout

`WorkbenchLayoutModel.fullscreen(...)` должен вычислять одну общую нижнюю панель вместо отдельных зон terminal и inventory.

Нужные результаты layout:

- `bottomPanelBounds: UiRect?`
- `bottomPanelTabStripBounds`
- `inventoryTabBounds`
- `terminalTabBounds`
- `hidePanelBounds`
- `bottomPanelContentBounds: UiRect?`

Высота editor затем вычисляется либо от:

- верхней границы `bottomPanelBounds`, либо
- области status bar, когда панель скрыта

Это убирает текущую неоднозначность, где editor сначала сжимается terminal dock, а затем inventory.

### Ответственность screen

`WorkbenchEditorScreen` должен:

- рендерить tab strip нижней панели
- рендерить только содержимое активной вкладки
- позиционировать inventory slots только когда активна вкладка inventory
- строить terminal layout только когда активна вкладка terminal

Экран остаётся владельцем terminal focus transitions, потому что уже координирует клавиатуру, мышь и состояние terminal input controller.

## Правила рендера

### Хром нижней панели

Нижняя панель должна иметь один общий chrome и один tab strip.

Визуальное различие между вкладками должно показывать:

- активную вкладку
- неактивную вкладку
- действие скрытия панели

Скрытое состояние должно оставаться обнаруживаемым через видимый control в header верстака или в нижнем tab strip.

### Слоты инвентаря

Перемещение inventory slots должно следовать активному layout.

Когда inventory не активен, экран не должен оставлять кликабельные hitbox слотов поверх неродственного UI.

Допустимые варианты реализации:

- переносить inventory slots вне видимой зоны взаимодействия
- подавлять взаимодействие со слотами на уровне screen, пока активны не-inventory вкладки

Нужно выбрать самый простой вариант, который остаётся совместим с menu behavior и test coverage.

### Подгонка terminal viewport

Bounds панели terminal, terminal surface и terminal status должны вычисляться из bounds контента terminal-вкладки.

Отрисованный character grid должен ограничиваться доступной шириной и высотой terminal-вкладки.

Это ключевое исправление, которое не даст размеру terminal снова зависеть от старых dock-предположений.

## Обработка ошибок и крайние случаи

- Если terminal snapshot отсутствует, terminal layout всё равно должен строиться из bounds terminal-вкладки с использованием текущих fallback dimensions.
- Если высота вкладки слишком мала, layout должен зажимать её до безопасного минимума, чтобы UI оставался отрисовываемым.
- Если активна вкладка `INVENTORY`, но слоты inventory нельзя безопасно расположить, screen должен fail closed и не оставлять скрытые кликабельные слоты.
- Если панель скрыта, terminal focus всегда должен сниматься.

## Стратегия тестирования

### Тесты layout

Нужно покрыть layout для:

- скрытого состояния панели
- состояния inventory с использованием `inventoryPanelHeight`
- состояния terminal с использованием `terminalPanelHeight`
- расширения editor по высоте, когда панель скрыта

### Тесты store

Нужно покрыть переходы состояния для:

- состояния нижней панели по умолчанию
- показа вкладки inventory
- показа вкладки terminal
- скрытия панели
- сохранения высоты вкладок при переключениях

### Screen-focused тесты

Нужно добавить проверку для:

- сброса terminal focus при уходе с terminal-вкладки
- неактивности inventory slots, когда активна не inventory-вкладка
- использования bottom panel content bounds вместо terminal dock bounds при построении terminal layout

### Ручная проверка

Ручная проверка должна подтвердить:

- IDE открывается с активной вкладкой terminal
- панель можно переключать между `Terminal`, `Inventory` и скрытым состоянием
- terminal всегда рендерится внутри рамки terminal-вкладки
- editor расширяется, когда панель скрыта
- inventory взаимодействует только на вкладке inventory

## Критерии успеха

Редизайн считается успешным, когда:

- нижняя часть IDE верстака работает как одна общая tabbed-панель
- terminal больше не рендерится отдельным dock над inventory
- размер terminal следует bounds terminal-вкладки
- обе вкладки можно скрыть через явное действие скрытия панели
- editor возвращает себе место, когда панель скрыта
- взаимодействие принимает только активная нижняя поверхность

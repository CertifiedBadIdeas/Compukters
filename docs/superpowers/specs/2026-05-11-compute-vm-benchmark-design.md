# Compute VM Benchmark Design

## Goal

Add an opt-in CPU-only benchmark for the CKL image VM so VM execution speed can be compared with the same workload running as optimized native Rust on the host machine.

## Non-Goals

- Do not benchmark display, filesystem, IPC, events, terminal rendering, or Minecraft tick scheduling.
- Do not change runtime quotas or gameplay behavior.
- Do not make the benchmark part of normal test runs.

## Workload

Use a deterministic `integer-mix` loop:

- 32-bit signed integer arithmetic.
- Multiply/add/xor/shift operations.
- A checksum returned from `main()` so the CKL VM and Rust baseline must agree.

This is intentionally small and boring: the point is to measure interpreter/native image VM hot-loop cost without hostcalls.

## Execution

- CKL source is generated by the profiling test with a literal iteration count.
- The source is compiled into a CK VM image.
- The image is run through the native JNI image VM until it returns a `Halt(Int)` signal.
- The native baseline is a Rust example with the same algorithm, run through `cargo run --release --example compute_benchmark_baseline`.
- Both sides run warmup and multiple samples; reports use the best sample.

## Gradle Entry Point

`./gradlew profileComputeVmBenchmark`

The task writes:

- `modules/compiler/build/reports/profiling/compute-vm-benchmark.tsv`
- `modules/compiler/build/reports/profiling/compute-vm-benchmark.md`

Configurable JVM properties:

- `ckl.benchmark.iterations`, default `500000`
- `ckl.benchmark.warmup.iterations`, default `50000`
- `ckl.benchmark.samples`, default `5`
